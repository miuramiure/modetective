# モデル探偵（仮称） ルールと進行

Balus を使って遊ぶ、モデル化と推測のゲームのアイデアです（試作版）。テーマカードと場面の選択肢は、別ファイル『テーマカード集』にまとめています。名前は仮称で、ほかの候補も検討中です。

**ひとことで言うと**：チームごとにお題を読んでモデルを描き、相手チームはそのモデルだけを見て「どんな場面で、何のために描いたモデルか、そこからどんな結論を出したか」を当てるゲームです。得点は2チームの合計なので、「伝わるモデル」を描くほど高得点になります。

## 1. ゲームの概要

**モデル探偵**は、モデルを描くチームと、そのモデルを読み解くチームに分かれて遊ぶ、モデル化と推測のゲームです。

- **モデリングフェーズ**：各チームにテーマカードが提示されます。各チームはカードの**お題**を読んでモデルを描き、モデルから得た**結論**を書きます。
- **読み取りフェーズ**：各チームは、同じグループの相手チームのモデルだけを見て、そのチームの**場面**、**目的**、**結論**を当てます。
- 2チームで1つの**グループ**になり、**グループの合計点**で他のグループと競います。

同じグループの2チームは対戦相手ではなく、味方です。どのチームも、「目的と結論が相手に伝わるモデル」を描くほど、グループの得点が上がります。

### お題の2つのモード

お題には2つのモードがあります。1セットの中では、全チームで同じモードを使うのが基本です。

| | シナリオモード | 聞き込みモード |
|---|---|---|
| お題の中身 | ゲーム設計側が、場面や設定（人数、時刻、条件など）を用意する | チームの中から**聞き込み対象**を1人決め、その人の実際の経験や事実を聞き出して、それをもとにモデリングする |
| テーマカード | 『テーマカード集』第1部（T01〜T28） | 『テーマカード集』第2部（K01〜K20） |
| よいところ | 条件がそろっているので、すぐにモデリングに入れる。同じお題のモデルを比べやすい | 本物の話なので、題材に手ざわりがある。聞き出す力（要求を引き出す力）も練習になる |
| 気になるところ | 設定が作りものなので、実感がわきにくいことがある | 聞き込みに時間を使う。話の量や中身が人によって違う |
| 向いている使い方 | 初めて遊ぶとき、得点を競うとき | ルールに慣れたあと、メンバーどうしをよく知りたいとき |

聞き込みモードの進め方は、5章フェーズ2の「聞き込みモードの進め方」を見てください。

### ねらい

- **ビューの理解**：同じ場面でも、どう切り取るかでモデルが変わることを体験する
- **モデリングの目的を意識する**：目的が伝わるモデルとは何かを考える
- **モデリング能力の向上**：限られた時間で、結論まで導けるモデルを描く練習をする
- **聞き出す力**（聞き込みモード）：相手の話から、モデルに必要な事実を引き出す練習をする

## 2. 用語

| 用語 | 意味 |
|---|---|
| 場面 | 読み取りフェーズで相手チームが当てる場面。一言で表される（例：カレーづくり、通勤）。選択肢リストから選ぶ |
| 目的 | 読み取りフェーズで相手チームが当てる、モデリングの目的。選択肢から選ぶ場合と、選択肢なしで答える場合がある（5章フェーズ3参照） |
| お題 | モデリングフェーズで、各チームがこれを読んでモデリングする文章。場面と目的の要素を含み、そのチームが出すべき結論に対する問いを含む |
| 結論 | 各チームがモデルを通して得た、お題の問いへの答え。読み取りフェーズで相手チームがこれを当てる |
| テーマカード | 場面・目的・お題・結論の形が書かれたカード。モデリングフェーズで各チームに提示される（カードの内容はすべて見てよい） |
| シナリオモード | ゲーム設計側が用意した場面や設定をもとにモデリングする、お題のモード |
| 聞き込みモード | チームの中の聞き込み対象の人から実際の経験や事実を聞き出し、それをもとにモデリングする、お題のモード |
| 聞き込み対象 | 聞き込みモードで、チームの中から1人選ばれ、自分の経験や事実を話す人。チームが1人のときは自分自身 |
| チーム | 1人以上。1セットの中で、モデリング（自分のカード）と読み取り（相手のモデル）の両方を行う |
| グループ | 2チームの組。得点はグループ単位で合計する |

## 3. 人数と構成

- **1チーム**：1人以上（推奨は2〜3人）
- **1グループ**：2チーム。**最小は2人**（1人×2チーム）
- **グループ数**：制限なし。1グループだけでも遊べます（その場合は過去の得点や目標点と比べます）
- **ファシリテーター**：1人。ブレイクアウトルームの操作、時間管理、採点を担当します。グループが多い場合は、採点補助を置きます

## 4. 準備するもの

オンラインで遊ぶことを前提にしています。

- **オンライン会議ツール**：Zoom や Teams など、**ブレイクアウトルーム**が使えるもの
- **Balus**：チームごとにモデルを描く場所（プロジェクトやダイアグラム）を用意し、参加者全員がログインできるようにしておきます
- **テーマカード**（『テーマカード集』第1部がシナリオモード、第2部が聞き込みモード）：共通カード方式なら2種類、個別カード方式ならグループ数×2種類（5章「カードの提示のしかた」参照）。チームごとにカードを送れるようにしておきます
- **目的の選択肢**（『テーマカード集』の各カード）：目的を選択肢から選ぶ場合だけ使います。読み取りフェーズで、相手チームのカードの分だけを見せられるようにしておきます
- **場面の選択肢リスト**（『テーマカード集』第3部）：そのセットで使うモードのリストを、読み取りフェーズで全員が見られる場所（Balus 上など）に置きます
- **結論を記入する場所**：チームごとに、モデルとは別に結論を書く場所（Balus 上など）を用意します
- **回答を記入する場所**（本書 7章）：チームごとに、読み取りの回答を書く場所（Balus 上など）を用意します
- **採点を記入する場所**（本書 8章）：ファシリテーターが得点を書き、全員に見せられる場所（Balus 上など）を用意します
- **タイマー**：ブレイクアウトルームの残り時間表示や、全体へのメッセージ送信で知らせます

### ブレイクアウトルームの割り当て

チームごとに1つのルームを用意します。ルーム名は「G1-A」「G1-B」「G2-A」…のように、グループとチームがわかる名前にしておくと、移動や呼び出しがしやすくなります。

| フェーズ | 参加者のいる場所 |
|---|---|
| 0 ルール説明 | メインルーム（全員） |
| 1 テーマカードの提示 | メインルームで説明したあと、チームのルームへ移動。テーマカードはルーム移動と同時に各チームへ送る |
| 2 モデリング | チームのルーム |
| 3 モデル読み取り | チームのルーム（そのまま）。Balus で相手チームのモデルを開く |
| 4 採点 | メインルーム（全員） |
| 5 全体共有 | メインルーム（全員）。ファシリテーターが Balus を画面共有する |

- フェーズ2から3へは、ルームを移動せずに続けます。ファシリテーターは、全体へのメッセージで「読み取りフェーズ開始」を知らせます。
- ファシリテーターは各ルームを巡回し、進み具合や、ルール違反（相手チームとの相談など）がないかを確かめます。

## 5. 1セットの流れ

1セットは約60分です（ルール説明は初回のみ）。

| # | フェーズ | 時間の目安 | 内容 |
|---|---|---|---|
| 0 | ルール説明 | 10分 | 初回のみ |
| 1 | テーマカードの提示 | 3分 | 各チームにテーマカードを1枚ずつ提示する |
| 2 | モデリング | 25分 | 各チームが、提示されたカードのお題について Balus でモデルを描き、結論を書く。聞き込みモードでは、はじめの5〜8分を聞き込みにあてる |
| 3 | モデル読み取り | 10分 | 各チームが相手チームのモデルを見て、場面・目的・結論を回答する |
| 4 | 採点 | 10分 | 各チームの結論とテーマカードを公開し、ファシリテーターが採点する |
| 5 | 全体共有 | 15分 | 高得点・低得点のグループのモデルを全体に見せ、解説と議論をする |

### フェーズ1：テーマカードの提示

各グループの2チームを、それぞれ**Aチーム**、**Bチーム**と呼びます。1グループの中では、AとBに**場面が違う**カードを提示します。『テーマカード集』第4部の同じ行に入る組み合わせも避けます。聞き込みモードでは、カードの「補足」に書かれた組み合わせ（K05とK19など）も避けます。

#### カードの提示のしかた（2つの方式）

| | 共通カード方式 | 個別カード方式 |
|---|---|---|
| 提示のしかた | 全グループのAチームに同じカードX、全グループのBチームに同じカードYを提示する | グループごとに違うカードの組を提示する |
| 使うカード | 1セットで2種類 | 1セットでグループ数×2種類 |
| よいところ | 同じお題から、グループごとに違うモデルが出てくるのを比べられる。お題の難しさが揃うので、グループ間の得点が公平になる | いろいろなテーマで、いろいろなモデルが出てくる。場として多様で、にぎやかになる |
| 気になるところ | 1セットで扱うテーマが2つだけになる | カードの難しさの差が、そのまま得点の差になる |
| 向いている使い方 | 得点を競う、モデルの描き分けを学ぶ | 初回のお試し、テーマの幅を楽しむ |

- **共通カード方式**では、他グループの同じお題のモデルが、モデリング中に見えないようにしておきます（下の「Balus の見せ方」参照）。
- **個別カード方式**では、提示するカードの★の数を揃えると、得点の不公平を小さくできます。
- 複数セット遊ぶ場合は、**1セット目は個別カード方式、2セット目は共通カード方式**のように組み合わせることもできます。
- **聞き込みモードで共通カード方式**にすると、同じお題でも、聞き込み対象の人によって中身もモデルも変わります。全体共有で並べて見ると、違いがよくわかります。

#### 提示するときの注意

- テーマカードは、場面・目的・お題・結論の形を含めて、**カードをまるごと**提示します。
- カードは、ブレイクアウトルームのチャットや、チームごとのメッセージで送ります。**メインルームのチャットに貼ると全員に見えてしまう**ので注意してください。
- 自分のチームのカードは、相手チームに見せません。

#### Balus の見せ方

| フェーズ | 見えてよいもの | 見えてはいけないもの |
|---|---|---|
| 2 モデリング | 自分のチームのモデルと結論 | 他のすべてのチームのモデルと結論 |
| 3 モデル読み取り | 自分のチームのモデルと結論、相手チームのモデル | 相手チームの結論、他グループのモデル |
| 4〜5 採点・全体共有 | すべて | ― |

> **要検討**：上の表のように見せ分ける方法を、Balus の機能で決める必要があります。例えば、チームごとに別のプロジェクトを作って閲覧権限をフェーズごとに付け替える、読み取りフェーズの開始時にファシリテーターが相手チームのモデルへのリンクを送る、などです。権限の切り替えができない場合は、「フェーズ2では他チームのモデルを開かない」という紳士協定で運用します。

### フェーズ2：モデリング

- 各チームは、提示されたカードのお題を読み、**モデル化の対象とビューを自分たちで決めて**、Balus でモデルを描きます。場面と目的はカードに書かれていますが、それをモデルでどう表すかはチームに任されています。
- モデルとは別に、**結論**を Balus 上に書きます。結論は、お題の問いへの答えです（例：「洗面所の待ちと忘れ物探しで時間を失っている」）。
- 時間内に結論を書けなかった場合は減点になります（6章）。

**モデリングのルール**

1. モデルに、**場面の一言**（選択肢リストにある言葉）や、**目的の文**を書いてはいけません。
2. モデルに、**お題の問いの文**や**結論**を書いてはいけません。場面・目的・結論は、モデルから読み取れるようにします。
3. お題に出てくる具体的な情報（「洗面所は1つ」「鉄板2枚」など）や、聞き込みで聞き出した事実は、要素として使ってかまいません。ただし聞き込みモードでは、人の実名、会社名、住所など、個人が特定できる情報はモデルに書きません（「上司」「取引先A」のように置き換えます）。
4. 相手チームと相談してはいけません。

**結論の書き方**

- お題の問いに、1〜3文で直接答えます。
- 結論がお題の問いに答えていない場合は、「未記述」として扱います。
- 結論は、読み取りフェーズの間は相手チームから見えないようにしておきます（フェーズ1「Balus の見せ方」参照）。
- **締め切りは、ファシリテーターが「読み取りフェーズ開始」を知らせた時点**です。それ以降に書き足した結論は、採点では「未記述」として扱います。

> **要検討**：結論を記入する場所（Balus 上など）を、読み取りフェーズの間は相手チームに見せないようにする方法を決める必要があります。
> **案**：結論だけは Balus に書かず、ファシリテーターへの個別メッセージ（会議ツールのチャットなど）で提出する。Balus の権限を切り替えなくても、結論が相手チームから見えず、提出時刻で締め切りも判定できる。採点のときに、ファシリテーターが全チームの結論をまとめて見せる。

#### 聞き込みモードの進め方

聞き込みモードでは、モデリングフェーズの25分を、次のように使います。

| 時間の目安 | やること |
|---|---|
| はじめの1分 | チームの中から**聞き込み対象**を1人決める。カードの系統（日常系・仕事系）を見て、話しやすい人を選ぶ。チームが1人のときは、自分自身が聞き込み対象になる |
| 5〜8分 | **聞き込み**。ほかのメンバーが、お題に沿って聞き込み対象の人に質問し、流れや事実を聞き出す。聞きながらメモや下書きのモデルを作ってもよい |
| 残り | モデリングと結論の記入。聞き込み対象の人もモデリングに加わってよい。足りない事実は、その場で聞き足してよい |

- **話したくないことは、話さなくてかまいません。** 聞き込み対象の人は、細部を変えたり、ぼかしたりしてもかまいません。質問する側も、深追いはしません。
- モデルに描いたこと以外の聞き込みの中身は、チームの外に出しません。全体共有でモデルを見せたり、聞き込みの話をしたりするときも、聞き込み対象の人がよいと言った範囲にとどめます。
- 聞き込みが長引いてモデリングの時間が足りなくならないよう、8分を過ぎたら聞き込みを切り上げます。ファシリテーターは、巡回のときに進み具合を確かめます。
- 結論は、聞き込みで聞いた事実をもとに、チームが考えて書きます。聞き込み対象の人の意見をそのまま書く必要はありません。

### フェーズ3：モデル読み取り

- 各チームは自分のチームのルームに残ったまま、Balus で相手チームのモデルを開きます。**モデルは見るだけで、編集してはいけません。**
- 相手チームのモデルを見て、回答を記入する場所（Balus 上など）に次の3つを書きます。
  - **場面**：選択肢リストから1つ選ぶ
  - **目的**：このモデルは何のために描かれたか（選択肢から1つ、または1文。下の「目的の答え方」参照）
  - **結論**：相手チームはこのモデルから何を結論したか（1〜3文）
- 相手チームに質問してはいけません。相手チームも説明してはいけません。モデルだけが手がかりです。
- 相手チームのテーマカードは見られません（選択肢ありの場合の「目的の選択肢」だけは見られます）。

#### 目的の答え方（2つのパターン）

目的は、選択肢から選ぶ答え方と、選択肢なしで答える答え方のどちらでも遊べます。何度か遊んでみて決める予定です。

| | 選択肢あり | 選択肢なし |
|---|---|---|
| 答え方 | 相手チームのカードにある「目的の選択肢」（5択）から1つ選ぶ | このモデルが何のために描かれたかを、1文で書く |
| 見せるもの | 相手チームのカードの「目的の選択肢」だけを、読み取りフェーズの開始時に見せる | なし |
| よいところ | 答えやすく、採点がぶれない。紛らわしい選択肢の中から選ぶので、モデルを細かく見比べることになる | 目的を自分の言葉で言い表す練習になる。モデルから読み取った内容がそのまま答えに出る |
| 気になるところ | 当てずっぽうでも5分の1で当たる | 「一致」「部分一致」の判定がぶれやすく、採点に時間がかかる |

- 目的の選択肢には場面の一言を含めていないので、選択肢を見ても場面はわかりません。
- 1回の遊びの中では、全グループで同じパターンを使います。

### フェーズ4：採点

- ファシリテーターがブレイクアウトルームを閉じ、全員をメインルームに戻します。
- 各チームの**結論**と**テーマカード**（場面・目的）を公開します。グループが多い場合は、ファシリテーターが結論と回答を記入した場所（Balus 上など）を画面共有して、全チーム分をまとめて見せます。
- ファシリテーターが、6章の基準で採点します。
- 判定が割れるときは、『テーマカード集』第4部の「判定の境界」に従います。

### フェーズ5：全体共有

高得点グループと低得点グループのモデルを、それぞれ1〜2組ずつ全体に見せます。議論の切り口の例は次のとおりです。

- 読み取ったチームは、モデルのどこを見て目的を読み取ったか。どこで読み違えたか
- モデルを描いたチームは、何を対象にし、どのビューで切ったか。ほかの切り方はあり得たか
- 結論は、モデルの形そのものに現れていたか（例：「待ち」が描かれていたか）
- 同じ場面で目的が違うカード（例：T09・T10・T28）が出ていれば、モデルを並べて違いを見る
- **共通カード方式のとき**：同じお題に対する各グループのモデルを並べ、対象やビューの選び方の違いと、それが得点にどう効いたかを見る
- **聞き込みモードのとき**：聞き込み対象の人に、チームの結論に納得できるかを聞いてみる。どんな質問が、モデルに効く事実を引き出したかも振り返る

## 6. 採点

得点は**グループの合計**です。1グループには「チームA→チームBの読み取り」と「チームB→チームAの読み取り」の2方向があり、方向ごとに採点して合計します。

### 1方向あたりの配点

| 項目 | 一致 | 部分一致 | 不一致 |
|---|---|---|---|
| 場面 | 2点 | ―（なし） | 0点 |
| 目的 | 4点 | 1点（選択肢なしの場合のみ） | 0点 |
| 結論 | 4点 | 2点 | 0点 |

- 1方向の満点は10点、グループの満点は20点です。
- 場面は選択肢があるので当たりやすく、配点を低めにしています。

### 減点

| 状況 | 扱い |
|---|---|
| モデルを描いたチームが時間内に結論を書けなかった（問いに答えていない結論を含む） | その方向は**−3点**。結論の得点は0点 |
| モデリングのルール1・2に違反した（場面の一言、問いの文、結論をモデルに書いた） | その方向は**−2点** |

### 判定の基準

**場面**

- カードの場面と同じものを選んでいれば一致です。
- 紛らわしい選択肢を選んだ場合は、『テーマカード集』第4部の「判定の境界」で「正解扱いとしてよい」とされているものに限り、一致とします。
- 聞き込みモードでは、聞き込みの中身によって題材がずれることがあります（例：K01で、移動が中心のモデルになった）。そのような場合の扱いも、第4部の「判定の境界」に書いています。

**目的**

- **選択肢ありの場合**：カードの目的と同じ選択肢を選んでいれば一致（4点）、それ以外は不一致（0点）です。部分一致はありません。
- **選択肢なしの場合**：「何を決めたいか／何を明らかにしたいか」で、次のように判定します。

  - 一致：カードの目的と、決めたいことが同じ（カードの「目的の判定メモ」にある言い方を含む）
  - 部分一致：方向は合っているが、ぼやけている、または広すぎる（例：「朝を効率化したい」）
  - 不一致：決めたいことが違う（例：正解は「遅れの原因をつきとめる」、回答は「朝ごはんの献立を決める」）

**結論**：モデルを描いたチームが書いた結論と比べて判定します。カードの模範解答とは比べません。

- 一致：モデルを描いたチームの結論の要点を含んでいる。要点が複数あるなら、そのすべてを含んでいる
- 部分一致：要点の一部だけを含んでいる
- 不一致：要点を含んでいない

※ 結論の良し悪し（現実的に正しいか）は採点しません。**モデルを通して伝わったかどうか**だけを見ます。

### 同点のとき

- 結論の得点が高いグループを上位とします。それでも同じなら、目的の得点で比べます。

## 7. 回答の記入項目

回答を記入する場所（Balus 上など）には、次の項目を用意します。

```
モデル探偵 回答
グループ：＿＿＿＿＿　チーム：＿＿＿＿＿（読み取ったモデル：チーム＿＿＿＿）

1. 場面（選択肢から1つ）：＿＿＿＿＿＿＿＿＿＿

2. 目的（このモデルは何のために描かれたか。選択肢ありなら1つ選ぶ、なしなら1文で書く）：
   ＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿

3. 結論（相手チームはこのモデルから何を結論したか）：
   ＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿
   ＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿＿
```

その回答にした理由（モデルのどこを見てそう読んだか）は書きません。解決編で回答を発表するときに、口頭で説明してもらいます。

## 8. 採点の記入項目

採点を記入する場所（Balus 上など）には、次の項目を用意します。

| グループ | 方向 | カード | 場面(2) | 目的(4) | 結論(4) | 減点 | 小計 |
|---|---|---|---|---|---|---|---|
| G1 | A→B | T__／K__ | | | | | |
| G1 | B→A | T__／K__ | | | | | |
| **G1 合計** | | | | | | | **/20** |

「A→B」は、チームAのモデルをチームBが読み取った方向です。カードの欄には、シナリオモードならT、聞き込みモードならKの番号を書きます。

## 9. ファシリテーター向けメモ

- **初回は★のカードから始める**と、ルールの理解に集中できます。初回はシナリオモードがおすすめです。
- **聞き込みモードは、日常系の★のカード（K01、K10、K11）から始める**と、誰でも話しやすく、聞き込みにも時間がかかりません。
- 聞き込みモードでは、仕事の話が出ることがあります。社外の人がいる場では、日常系のカードを選ぶと安心です。
- **ダミーの選択肢は、何回か遊んだら入れ替えてください。** 正解になり得る場面を覚えられると、場面の推測が簡単になりすぎます。
- **結論の部分一致の判定が一番ぶれやすい**ところです。採点補助を置く場合は、最初の数件をファシリテーターと一緒に判定して、目線を合わせてください。
- モデリング時間が足りないチームが多ければ、時間を30分に延ばすか、★の少ないカードを提示します。
