## Step 1：リポジトリを作る（PC）
コマンドプロンプトを開きます（管理者でなくてよい）。

作業用のフォルダへ移ります。
```
cd /d C:\work
```
GitHubに非公開リポジトリを作って、手元に複製します。
```
gh repo create miuramiure/modetective --private --clone
```
成功すると `C:\work\modetective` ができます（中身は空）。中身のコピーは、最初の依頼で Claude Code がやります。

## Step 2：画面の置き場所（ConoHa WING）
ITBの itb.m-miura.jp と同じ手順です。
1. ConoHaのコントロールパネル →［WING］→［サイト管理］→［サイト設定］の切り替えで、m-miura.jp を選んで［＋サブドメイン］
2. サブドメイン名に `modetective` を入れて保存（ドキュメントルートは `public_html/modetective.m-miura.jp` になるはず）
3. ［サイトセキュリティ］→［独自SSL］→［無料独自SSL］を利用設定ON（反映に数十分かかることがある）
4. 確認：しばらくしてから https://modetective.m-miura.jp を開き、WINGの初期ページ（または空のページ）が鍵マーク付きで出ればOK

DNSは同じConoHaなので、itb のときと同じく自動で設定される見込みです（ConoHaのDNS画面で `modetective` のAレコード → 160.251.148.25 を確認）。

## Step 3：VMに入って、ユーザーとフォルダを作る
PCのコマンドプロンプトから、IAP経由でVMに入ります。
```
gcloud compute ssh itb-play --zone=us-west1-b --project=itb-online --tunnel-through-iap
```
ここから先（Step 5まで）は**VMの中（Linuxのbash）**で打つコマンドです。

アプリ実行用のユーザー（ログイン不可）を作ります。
```
sudo useradd --system --home /opt/modetective --shell /usr/sbin/nologin mdt
```
アプリとデータと設定のフォルダを作ります。
```
sudo mkdir -p /opt/modetective/releases /var/lib/modetective /etc/modetective
```
```
sudo chown -R mdt:mdt /opt/modetective /var/lib/modetective && sudo chmod 750 /etc/modetective
```
確認（3つとも出ればOK）：
```
ls -ld /opt/modetective /var/lib/modetective /etc/modetective
```

## Step 4：Caddyに振り分けを足す
いまの設定を確かめます（games-api.m-miura.jp のブロックに `handle /illuminatea/*` があるはず）。
```
sudo cat /etc/caddy/Caddyfile
```
各ゲームの振り分けファイルを置くフォルダを作ります。
```
sudo mkdir -p /etc/caddy/games.d
```
modetective の振り分けファイルを作ります（3行をまとめて貼ってEnter）。
```
printf 'handle /modetective/* {\n    reverse_proxy 127.0.0.1:3102\n}\n' | sudo tee /etc/caddy/games.d/modetective.caddy
```
Caddyfileを開き、`games-api.m-miura.jp {` の次の行あたり（`handle /illuminatea/*` の前）に1行足します。
```
sudo nano /etc/caddy/Caddyfile
```
足す行：
```
    import /etc/caddy/games.d/*.caddy
```
（nano：Ctrl+O → Enter で保存、Ctrl+X で終了）

設定が正しいか確かめます。`Valid configuration` と出ればOK。
```
sudo caddy validate --config /etc/caddy/Caddyfile
```
反映します（ITBは止まりません）。
```
sudo systemctl reload caddy
```
ITBが無事か確かめます（`{"ok":true` のような応答が出ればOK）。
```
curl -s https://games-api.m-miura.jp/illuminatea/api/health
```

## Step 5：仮のサーバーで疎通を確かめる
仮のページを作ります。
```
mkdir -p /tmp/mdt-hello/modetective && echo "modetective ok" > /tmp/mdt-hello/modetective/index.html
```
仮のサーバーを3102番で動かします（この画面はこのままにしておく）。
```
cd /tmp/mdt-hello && python3 -m http.server 3102 --bind 127.0.0.1
```
PCのブラウザで https://games-api.m-miura.jp/modetective/ を開き、`modetective ok` と出ればOK。
確認できたら、VMの画面で Ctrl+C で仮のサーバーを止め、片付けます。
```
rm -rf /tmp/mdt-hello
```
VMから出ます。
```
exit
```
※ 仮のサーバーを止めたあとは、/modetective/ は 502 エラーになります（本物のサーバーを置くまで正常）。

## Step 6：ITBリポジトリにも反映（PC）
VMのCaddyfileを直接直したので、ITBのリポジトリ（C:\work\itb の infra/caddy の Caddyfile）にも同じ1行を入れておきます。入れておかないと、ITBのデプロイでCaddyfileが上書きされたときに modetective の振り分けが消えます。
ITB側の Claude Code に次のように頼めば足ります。
> infra/caddy の Caddyfile の games-api.m-miura.jp ブロックに `import /etc/caddy/games.d/*.caddy` を1行足して（handle /illuminatea/* の前）。/etc/caddy/games.d/ は各ゲームのリポジトリが自分の振り分けファイルを置く場所。コミットしてpushまで。

## Step 7：GM合言葉

- サーバーへの設定は、M4（デプロイ）で Claude Code が用意するスクリプトでハッシュにして /etc/modetective/env に置きます。合言葉そのものをリポジトリやチャットに書かないでください。
