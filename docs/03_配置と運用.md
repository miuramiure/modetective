# 配置と運用（modetective v2、M4〜）
対象：Windows のコマンドプロンプト（cmd）。リポジトリは `C:\work\modetective`。
前提：[02_環境構築手順.md](02_環境構築手順.md) の Step 1〜6 が済んでいること。

## 0. 全体
| 何を | どこへ | コマンド |
|---|---|---|
| サーバー（Node.js） | GCP の VM `itb-play`（`/opt/modetective/current`、systemd `modetective`、ポート3102、Caddy が `https://games-api.m-miura.jp/modetective/*` を中継） | `pnpm deploy:server` |
| 画面（Vite のビルド結果） | ConoHa WING `public_html/modetective.m-miura.jp/`（`https://modetective.m-miura.jp`） | `pnpm deploy:web`（SSH鍵）または `pnpm deploy:web -- --zip`（ファイルマネージャー用） |
| GM合言葉 | VM の `/etc/modetective/env`（ハッシュだけ） | `pnpm gm-pass` |
| 部屋 | VM の `/var/lib/modetective/rooms.json`（48時間で消える） | ― |

VM で触るのは modetective のものだけです（`/opt/modetective`、`/etc/modetective`、`/var/lib/modetective`、`/etc/systemd/system/modetective.service`、`/etc/caddy/games.d/modetective.caddy`）。ITB のファイルとサービスには触りません（Caddy の reload だけは共通。reload では ITB は止まりません）。

はじめに、リポジトリのフォルダへ移ります（以下、すべてこのフォルダで打ちます）。
```
cd /d C:\work\modetective
```

## 1. サーバーを配置する
```
pnpm deploy:server
```
- 手元でビルド → tar にまとめる → IAP 経由で VM に送る → VM で `infra/scripts/install-release.sh` が動きます。
- VM の中では：`/opt/modetective/releases/<日時>/` に展開 → socket.io を入れる → systemd・Caddy の設定を入れる → `current` を切り替えて `modetective` を再起動。古い版は新しい5つを残して消します。
- 最後に `配置後の health： {"ok":true,...}` と出れば成功です。
- 遊んでいる最中に配置しても、部屋は保存から戻り、画面は自動でつなぎ直します（数秒止まります）。
- 最初の1回は、GM合言葉がまだないので起動しません（次の 2. へ）。

## 2. GM合言葉を設定・変更する（最初の1回と、変えたいとき）
```
pnpm gm-pass
```
- 合言葉を2回入れます（画面には `*` だけ出ます）。全角・半角と前後の空白は区別しません。
- 手元でハッシュにして、ハッシュだけを VM の `/etc/modetective/env` に書き、サーバーを再起動します。
- `サーバーを再起動しました（新しい合言葉で動いています）` と出れば成功です。
- 合言葉そのものは、リポジトリ・チャット・ファイルに書かないでください。GM役の人には口頭などで伝えます。
- 変えると、作成済みの部屋のGM画面はそのまま使えます（GMトークンで入っているため）。別の端末から入り直すときは新しい合言葉を使います。

## 3. 画面を配置する
### 3a. SSH 鍵で送る（ふだんはこちら）
最初の1回だけ、送り先を書いたファイルを作ります。ITB と同じ WING なので、`C:\work\itb\tools\deploy\wing.env` と同じ値で、`WING_PATH` だけ `public_html/modetective.m-miura.jp` にします。
```
copy infra\scripts\wing.env.example infra\scripts\wing.env
```
```
notepad infra\scripts\wing.env
```
配置します（`配置しました` と出れば成功）。
```
pnpm deploy:web
```
### 3b. ファイルマネージャーで上げる（SSH が使えないとき）
zip を作ります（`build\modetective-web-<日時>.zip`）。
```
pnpm deploy:web -- --zip
```
WING のファイルマネージャーで `public_html/modetective.m-miura.jp/` に zip を上げて展開します（`.htaccess` を含みます。古い `index.html` は上書き）。

## 4. 動作の確認
- https://games-api.m-miura.jp/modetective/api/health が `{"ok":true,...}`（`version` が配置した日時）
- https://modetective.m-miura.jp を開くと「ゲームをはじめる（ゲームマスター用）」が出る
- GM合言葉で部屋を作り、参加者URL（`https://modetective.m-miura.jp/?r=部屋コード`）をスマホなど別の端末で開いて入れる
- ITB が無事：https://games-api.m-miura.jp/illuminatea/api/health が `{"ok":true,...}`

## 5. ログ・状態を見る（VM の中で）
VM に入ります。
```
gcloud compute ssh itb-play --zone us-west1-b --project itb-online --tunnel-through-iap
```
ここから VM の中です。ログ：
```
sudo journalctl -u modetective -n 50 --no-pager
```
状態とメモリ：
```
systemctl status modetective --no-pager
```
VM から出ます。
```
exit
```

## 6. 前の版に戻す（VM の中で）
版の一覧を見ます（新しい順）。
```
ls -1t /opt/modetective/releases/
```
戻したい版（`<日時>`）に切り替えて再起動します。
```
sudo ln -sfn /opt/modetective/releases/<日時> /opt/modetective/current && sudo systemctl restart modetective
```

## 7. 止める・消す（VM の中で）
止める（再起動しても起動しないようにする）：
```
sudo systemctl disable --now modetective
```
部屋をすべて消す（遊んでいる人がいないときに）：
```
sudo systemctl stop modetective && sudo rm -f /var/lib/modetective/rooms.json && sudo systemctl start modetective
```
